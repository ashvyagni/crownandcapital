# ADR-001: Git Baseline & Doc Truth

## Status
accepted

## Context
The `crownandcapital` repository had no git history initially. The project began with a broken build (`npm run lint` failed), stale documentation (`docs/TESTING.md` claimed 5 Vitest files / 30 tests but actual was 7/45), and no reproducible environment. Multiple agents worked across ~24 commits to establish a truthful baseline.

## Context
- No git history existed at root level
- Documentation claims (test counts, build sizes) did not match measured results
- Multiple concurrent agent sessions worked on overlapping feature areas
- Security, a11y, and performance concerns needed independent review

## Decision
1. **Initialize git repository** with a truthful initial commit capturing the green baseline (`d1f9538`: lint, unit 37/37, server 2/2, e2e 21/21 as verified before doc reconciliation).
2. **Reconcile all documentation** to match measured results:
   - `README.md`: unit test count 45 (was 37, then 41, now 45)
   - `docs/TESTING.md`: test counts, build-size evidence, e2e run dates
   - Remove stale claims, add verification envelopes
3. **Artifact cleanup**: delete `tests/reference-inspection.mjs` (external scraper), keep `test-results/` screenshots ignored via `.gitignore`, ignore `.data/`, `dist/`, `.vite/`.
4. **Commit 1**: `d1f9538 baseline: green lint/37 unit/2 server/21 e2e verified before doc reconciliation`
5. **Commit 2**: `f377512 docs: reconcile test counts with fresh runs; drop external reference-inspection scraper`
6. **Subsequent commits** progressively fixed build, added features, resolved review findings, and updated docs to current truth.

## Alternatives considered
- Skip git init: would lose recoverability and commit audit trail — rejected.
- Keep stale doc claims: would mislead future contributors — rejected.
- No artifact cleanup: would track unreliable files in version control — rejected.

## ADR-002 (future): Receipts Cap Policy
- **Context**: `RECEIPT_CAP = 500` implemented via `splice(0, n)` after `reconcile(s)` in `applyCommand`.
- **Decision**: cap keeps newest 500 entries; legacy sessions self-repair on first new command. No enforcement in `validateSession` (per-entry checks only).
